# Yard exercise station: authored art draft

The existing `yard-basic` room plan is an 8×8 outdoor square with `objects: []`. All 19 object types in the other authored plans already resolve to oblique Blender catalogs; duplicating one would not add a missing asset. This draft supplies a new 2×1 outdoor exercise station for a later content change by the integrator. It is **not yet a buildable object** and is intentionally absent from the live oblique registry and object mapping until the Yard content path can place it.

The [twelve-pose contact sheet](poses.png) displays the actual Blender model at four yaws and three camera elevations. It has a tall pull-up bridge and a low parallel grip on four rubber anchored plates. The materials use the existing muted steel/rubber/warm accent palette; all geometry stays inside the centered 2×1 footprint. The visible feet begin at ground Z=0, top height is 1.7 tiles. Model identity: `furniture.yard.exercise-station`; authored source: `assets/source/blender/furniture.yard.exercise-station.blend`.

`tooling/blender/create-yard-exercise-station.py` rebuilds the source in Blender 5.2.1. `tooling/blender/render-yard-exercise-station-oblique.py` exports 12 yaw × 6 elevation poses (72) at 256×256, nominal 128 px/tile, centered pivot `[128,128]`, camera target `[1,0.5,0.82]`. The renderer checks every transparent border before writing SHA-named PNGs and `public/game-content/oblique-furniture.yard-exercise-station.v1.json`. The catalog test checks the source hash and all 72 frame hashes. Full runtime placement, collision, save/load and Full HD visual behavior still depend on the content definition and consumer mapping; this sheet is a source-art check, not gameplay acceptance.

Verification: all 72 Blender renders passed the border gate; the twelve inspected contact-sheet poses retain the same anchored feet, with alpha bounds fully inside the 256×256 image at yaw 0/90/180/270 and elevation 20/40/70. The focused catalog and research-index tests passed 6/6. Replacing exactly the first frame's stored SHA with zeroes made the catalog test fail 1/1 at that PNG; restoring the original manifest made it pass 1/1. No browser test has been run because the asset is not yet placed by production content.

Proposed truthful labels for the future buildable content decision: **PL: „Stanowisko ćwiczeń”**, **EN: “Exercise station”**. Intended function is visual equipment for a Yard. No exercise, health or recreation effect is claimed until simulation implements one. The model is not added to player-facing catalog text by this draft.
