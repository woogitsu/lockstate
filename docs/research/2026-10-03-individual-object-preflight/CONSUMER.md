## Freshness and query cost

Renderer geometry revision is insufficient: a pending secondary footprint claim
may change admission without replacing drawn geometry. Freshness therefore uses
existing authoritative publications:

- Forced `simulation/status-counts` after paused command dispatch, including the
  same tick, invalidates a stationary aim immediately.
- Changed unsolicited `simulation/clock-state` ticks invalidate running aims after
  real dispatch/completion. A correlated clock acknowledgement does not pretend
  a command already ran.
- `simulation/ready`/`simulation/stopped` disarm/reset. The existing persistence
  worker-availability callback also clears the object tool before New/Load claims.

There is no query on every animation frame. A stationary idle paused aim requests
once; 100 further paints in the real pending-claim test add zero queries. Running
refresh is bounded by existing publications (clock ceiling 250 ms, status-counts
ceiling 500 ms plus existing command/refusal event publications), not pointer or
frame rate. No new snapshot polling, channel kind or simulation publication was
added. In-flight old-session requests retain the existing requester's 15-second
timeout; ownership prevents their delayed result from painting another session.
