# Weatherproof Yard waste bin for the existing object

`object.waste-bin` already has an indoor Blender model: `fixture.cell.waste_bin.blend`, with a cylindrical body, pedal and hinged lid. This new model is a **visual variant of that same 1×1 object**, not a new construction item. It uses an anchored rectangular petrol-steel shell, stainless ribs, rain hood and recessed front aperture. It does not change price, capabilities or saved identity.

The source is `assets/source/blender/fixture.yard.steel-waste-bin.blend`, generated by `tooling/blender/create-yard-waste-bin.py`. Blender 5.2.1 evaluated mesh vertices including modifiers and checked these minimum-corner bounds: **X [0.120,0.880], Y [0.098,0.893], Z [0,1.120]**. No visible geometry crosses the occupied 1×1 square.

`tooling/blender/render-yard-waste-bin-oblique.py` exports **72 poses** at 256×256, with yaw 0…330° by 30° and elevation 20…70° by 10°. Source and manifest camera targets are both `[0.5,0.5,0.62]`. The orthographic span is exactly four tiles: `256 / 4 = 64` nominal pixels per tile, matching runtime world scaling. The exporter strips volatile PNG metadata and refuses any non-transparent border pixel. The [12-view contact sheet](poses.png) is built from SHA-checked frames; it shows all four cardinal sides at three elevations.

Two complete exports produced the identical manifest SHA-256 `a549c1bc4ffa54287f741e1d836a29495d9b5080d8d3634fdccf5c54ac6f58db`. The focused test checks source and all 72 frame hashes plus the exact resolution-to-orthographic-scale relation. Corrupting the first frame hash made it fail on actual PNG bytes; changing scale 4.0 to 3.7 made it fail on `256/3.7 != 64`; both restores passed. A contextual runtime selector and real player Save/Load pixel proof are subsequent work.
