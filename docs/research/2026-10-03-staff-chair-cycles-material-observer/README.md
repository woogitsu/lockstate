## Obtained source experiment: palette-only candidate rejected

The actual builder gives the seat pad centre `(0,.09,.648)`, dimensions
`(.45,.45,.092)`, and canonical min-corner translation `(.5,.5,0)`.
Using the real64px-per-tile orthographic basis and camera target
`(.5,.5,.6600000262260437)`, the experiment projects an inset28cm square on
the actual seat top into the existing60/e40 and300/e40 PNGs. These are
analytically projected opaque interior samples, not a Blender material mask.
Each contains207 opaque source pixels; together they supply55 distinct RGB
gradient values. No screenshot or network response supplies their colours.

That palette alone is insufficient: on the genuine default wooden chair it
accepts56 pixels at60/e40 and reaches350 across the72 actual default frames.
This candidate is rejected; the native `>40` rule is not reduced to fit it.
`source-palette-original-rejected.json` retains every actual source count and
the two projected polygons. `source-prototype.cjs.txt` is an inert historical
generator, not a new executable outside typechecking.

The next bounded candidate must discriminate the authored gradient against
the real default body as well: independently pinned source-gradient membership
plus a default-body colour veto, with an actual omission of that veto returning
RED. It must still pass the original native rectangles/floor on real q0/q1
photos; that result is pending. The colour reading cannot establish native
acceptance, correct object context or delivered texture use by itself.
