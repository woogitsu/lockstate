# Handover, 2026-08-26 — read this before touching anything

You are taking over Lockstate, a deterministic prison-management simulation in
TypeScript. This file is the state of the world at the end of a long session, and
it is written to be read once, in order, before you make a change.

`AGENTS.md` is the canonical contract and it outranks this file. `CLAUDE.md` adds
a few rules. Read both. Where this document and the code disagree, **the code is
right and this document is what rotted** — that is not a formality, it is the
single most common defect in this repository and there are seven examples of it
below.

## What the game can actually do

A player can buy materials and cancel a purchase for an exact refund; zone a
room; build a wall and a real door that navigation crosses; place any of 21
buildables; remove an object; cancel an unbuilt order; withdraw one queued build
order; admit a prisoner who is then housed, sleeps and uses the toilet; hire a
guard who is posted or walks a real route to its post; and watch the state pay
300 minor units per occupied place at the end of each in-game day.

Since #398 a new session derives one security sector, one deployment requirement
and one watched sector id from the world, so **a riot is reachable from the front
door**: measured at seed `0x396`, a severity-6 riot opens at tick 15,600 out of
real needs and real understaffing, three guards hired in reaction walk to the
post tile, the sector locks down, and it resolves at 15,681 with nobody injured.
Three things are still inert, each for its own reason and each stated rather than
smoothed over: **patrol** (no derived route), **lockdown's physical effect** (no
derived perimeter — the strongest argument for giving the player a
sector-drawing gesture), and **contraband search**, which was never about sectors
at all: `SearchSystem.submitOrder` has no caller in `src/`.
Construction runs one order at a time. Two beds in one zoned 3x3 cell house two
prisoners, so the cell-sharing rating decides real allocations. An incident costs
the prisoner who was in it: a lapsed riot moves a tier and their needs collapse,
and clean conduct reverses it to a floor one tier above someone who never
offended. A save taken mid-incident no longer strands the responders or the
lockdown.

**Two product gaps, in order of value:**

1. **Sanctions do not exist.** ADR 0032 delivers the finding and the moving tier,
   but **nothing relocates a placed prisoner**, so #80's solitary placement and
   loss of association are undelivered. This is the next real feature and the
   seam is already there.
2. **There is still no failure mode except running out of money.** Occupancy is
   hard-gated rather than degrading, so overcrowding is unrepresentable. #362
   established this deliberately rather than by omission — read it before
   proposing a fix. **But note one correction to that record:**
   `docs/research/2026-08-26-failure-modes.md` §3's mutual-exclusion finding —
   named by its own §7 as the record's strongest claim — is **false**.
   `requestAdmission` refuses only when *no* accommodation instance exists, not
   when one is full, so an unhoused arrival's `safety` decays to zero (measured
   252 → 207 → 0). Its probe admitted one prisoner into a furnished cell, so
   there was nobody unhoused to be the pressure — shape 3 above, in a research
   probe rather than a test. There may be more of a failure mode here than the
   record thinks.

## Four defect shapes that dominate this repository

Hunt these before you run any generic checklist. Every one of them was found by
reading, and all four cost real work today.

**1. A false sentence that no test can read.** This codebase carries long
explanatory comments and they are load-bearing, but nothing verifies English. The
sharpest form is not rot: **a claim can be false the day it is written.**
`STATUS-QUEUE.md` §5's ADR 0027 entry generalised from a unit test whose fixture
places nothing, while an integration test had been measuring the opposite since
#320 — confirmed with `git merge-base --is-ancestor`. ADR 0007 justified
flow-field sharing by asserting it was *"mathematically identical to running
#21's destination-rooted search"*; #21's search was rooted at the **origin**. Cost
is symmetric so the distances agreed and the *predecessors* did not, which is why
nobody noticed. **Check when a claim became false, not just that it is.** A claim
about an absence — "nothing calls this", "not yet", "the only" — rots most, because
adding the thing never touches the comment.

**2. An argument resting on a count that a later change multiplied.** ADR 0031
argued a layout trade at 2 catalogue rows, was amended at 4, and was approved at
21. Nothing re-read the argument when the number moved. **An argument resting on a
count should name the count and where it lives**, so the next reader checks it in
one command instead of trusting it.

**3. A guard whose fixture cannot reach the mechanism it names** (#375). Six
instances in one day. A tripwire whose comment said *"the day capacity is derived
from placed objects, this case fails"* — that day came and it stayed green,
because it zones an *empty* rectangle and an empty rectangle holds nobody under
both designs. Deleting the generation term from `isAlive` left 2,229 tests green,
because every assertion sat between a `destroy` and the next `spawn` and
short-circuited before reaching it. Eight of sixteen `loadSnapshot` no-op
mutations survived the whole suite, because the file compared a restored bundle
against another restored bundle. **Highest-risk shapes: an assertion pinning
`0`/`[]`/`undefined`; a round-trip through one object; a fixture that builds an
empty instance of the thing whose non-empty behaviour is the subject.**

**4. A module that is imported, constructed and stepped, but that no production
path ever supplies data to.** #396: `securitySectors.register` had one call site,
inside the restore path, reading a save payload — so deployment, incident response
and sector risk were **inert in every session a player could start**, and ADR
0032's incident consequences with them. A module-graph walk cannot see this; the
modules *are* in the graph. The detectable asymmetry is **a registry the
composition root constructs and only the restore path writes to**, which is also
what `ProcurementSystem.cancel` looked like before #392.

#398 fixed it, and the fix carries the more useful lesson: **the premise was
wrong about the count.** It was *three* empty registries, not one — a sector
alone changes nothing, because `DeploymentSystem.requiredGuardCountFor` answers
`0` with no schedule and `IncidentTriggerSystem` samples only the ids it is
handed. Registering the sector would have *looked* like a fix and measured as
nothing. When you find one of these, check whether the thing you are filling is
the only empty one.

Nobody has looked for the next instance.

## Structural things that are broken and are not bugs

**The ADR queue rule is unsatisfiable under concurrency.** `STATUS-QUEUE.md` §2
says *"any commit that adds an outstanding ADR adds an entry here in the same
commit"*. That assumes one writer. **Four ADRs — 0032, 0033, 0034, 0035 — were
accepted having never appeared in it**, every time because the file was held by
other work while their authors had it named as out of scope. Every author did the
right thing (debt in the ADR's Status, entry quoted in the PR) and every time the
approval arrived before the entry. The rule has now failed more often than it has
worked. The fix is structural — one file per entry in a directory, so two commits
can add two entries without touching each other — and it is overdue.

**Next-free numbering is also a claim about one instant.** Two agents both took
0034 within the hour, each having correctly enumerated open pull requests: the
other branch had not opened its PR yet. A number is not held until something is
pushed. No cheaper check closes that window; **pre-committing in the ADR text to
renumbering** is the only thing that has kept three collisions from becoming
arguments.

**A decision that changes no `Status` line has no home here.**
`adr-numbering-contract.test.ts` counts documents by their `Status` line, so an
**amendment** to an accepted ADR is invisible to every gate. While ADR 0007's
amendment was pending, its §2 entry was the only record a decision was
outstanding; deleting the entry on acceptance re-opened that gap, and the
amendment's own opening paragraph is now the only record it ever was.

**`adr-status-reference-contract.test.ts` matches on the status word and cannot
tell an assertion from a denial**, nor a general statement about a *shape* from a
claim about a particular ADR. Both `docs/adr/README.md` and ADR 0031 carry a
sentence worded awkwardly for exactly that reason, with the reason written beside
it. Do not "fix" the wording.

## How to work here

**Never report a result you did not obtain.** Run it, paste it. This project has
paid hours for confident false findings, including three external audit reports
that cited file paths and line numbers for code they never opened — a report that
quotes docs correctly but invents the code side reads as the most rigorous kind
and is the most dangerous.

**A green suite is not a guarded suite.** A test proves nothing until you have
mutated the code and watched it go red. When you add a test, run it against the
unfixed code first and keep both outputs.

**Never write a fixture that supplies both sides of a comparison** — an expected
value computed by the code under test holds for any implementation.

**Determinism is the property most of the suite exists to protect.** Fixed 50ms
tick in a Web Worker; 2,400 ticks is one in-game day. Named seeded RNG streams,
canonical `(y, x)` iteration, integer minor units with carried remainders rather
than floats, no `Math.random`/`Date.now`/`performance.now` anywhere near
simulation state, and no `Set`/`Map` insertion order deciding an outcome. A
restored session must agree with the live one it came from.

**A command acknowledgement means RECEIVED, never "took effect."** A refusal that
reaches no player-visible surface is a real bug here, not a cosmetic one — and a
refusal reason must come from an exhaustive `Record` over a named union, so a
boolean return will fail `simulation-refusals.test.ts`.

**ADR 0011:** no human-readable text under `src/ui/hud/**` — localization keys
only, with entries in `src/content/default-locale-en.ts` — and `src/ui/hud/**`
imports nothing from `src/simulation/**`.

**Propose an ADR rather than deciding architecture in code, and never
self-approve one.** An amendment section on an accepted ADR is the right shape
when a decision needs correcting rather than replacing.

**Extending a pinned list is fine** — that is what adding a system looks like, and
`tests/determinism/kernel-system-order.test.ts` shows how to do it honestly.
**Lowering a floor, weakening an assertion or `.skip`ping a test is not.**

## Working with agents, if you have them

Nine ran cleanly in parallel today once each was told to **create its own git
worktree as its first action**. Every collision came from the shared tree or from
shared ADR *numbers*, never from the count: three agents committed to local `main`
or moved another's branch pointer, and one left a `& 0xF` mutation-testing edit
behind that a fourth had to revert. Check `git log origin/main..main` at every
stopping point. Never `git add -A`. No scratch files inside `tests/` — a stray
probe broke a `pnpm verify` collection twice.

**Serialise within a feature area, parallelise across unrelated ones.** Name each
agent's surface and the others' explicitly. And watch for two agents converging on
one fact from different directions: #381 rediscovered at length something #371 had
put on `main` one commit earlier.

**The instruction that mattered most: tell every agent that correcting a premise
you gave it is welcome and expected.** It happened well over a dozen times today
and caught an issue's own "smallest fix" being insufficient, two ADR sentences
false the day they were written, two ADR premises false, one issue already fixed
so no fix should be invented, a task described as "the core of this work" already
merged, and several of my own errors. **An agent reporting "already fixed, here
are the numbers" is doing the job**, and so is one saying "your preferred approach
is not achievable, here is the trace".

## Merging

One at a time, squash. Check **mergeability and coherence separately** —
`git merge-tree --write-tree` can come back clean while the merged prose says the
same thing twice, so when two PRs touch one document, merge locally in a
throwaway worktree and run the relevant gates on the result. On conflict, merge
`main` **into** the branch and resolve toward whichever side is factually
correct, expecting both sides to be half right: compose, do not choose. Never
force-push over work you did not author. `405 Base branch was modified` just
means a release bump landed mid-merge — retry.

Before merging, spot-check what a green suite cannot tell you: no pinned floor
lowered, no assertion weakened, any ADR amended rather than self-approved, the
change's headline property actually asserted somewhere, and — for a docs-only or
comment-only claim — that the diff really is comment-only.

A CI `verify` job sitting queued for twenty minutes is usually your own agents
saturating the runner, not a fault.
